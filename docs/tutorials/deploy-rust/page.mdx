# Deploy Rust on Your Own Server

**Push your Rust project and Temps compiles a release build in a multi-stage Docker image** — BuildKit cache mounts keep the Cargo registry and `target/` directory between builds, and the binary runs on a Debian slim image. {{ className: 'lead' }}

---

## Quickstart {{ anchor: true, id: 'quickstart' }}

From your project root, deploy with your preferred package manager:

<CliCommands commands={[
  { args: "up" },
]} />

Temps detects your `Cargo.toml`, compiles a release build, and runs it on a Debian slim image. The toolchain comes from `rust-toolchain.toml` or `rust-toolchain`, and defaults to `stable`. The first build compiles every dependency; later builds reuse the cached registry and `target/` directory.

Temps builds the binary named by `default-run` in `Cargo.toml`, otherwise the only `[[bin]]`, otherwise the package name. If `Cargo.toml` declares several binaries, set `default-run` to choose one.

---

## What Temps handles automatically {{ anchor: true, id: 'what-temps-handles-automatically' }}

| Feature | How Temps handles it |
| ------- | -------------------- |
| Build | `cargo build --release --bin <name>` (with `--locked` when `Cargo.lock` is committed) |
| Caching | BuildKit cache mounts for the Cargo registry, git dependencies and `target/` |
| Image | Multi-stage: the binary is copied into a Debian slim runtime image |
| HTTPS | Let's Encrypt, auto-renewed |
| Port | `PORT` env var injected, defaults to 8080 |
| Startup | Near-instant, a single compiled binary |

## Custom Dockerfile (optional) {{ anchor: true, id: 'dockerfile-with-cargo-chef' }}

If you want full control over the build, add your own `Dockerfile`; Temps uses it instead of generating one. For example, with `cargo-chef`:

```dockerfile
FROM lukemathwalker/cargo-chef:latest-rust-1 AS chef
WORKDIR /app

FROM chef AS planner
COPY . .
RUN cargo chef prepare --recipe-path recipe.json

FROM chef AS builder
COPY --from=planner /app/recipe.json recipe.json
RUN cargo chef cook --release --recipe-path recipe.json
COPY . .
RUN cargo build --release --bin my-app

FROM debian:bookworm-slim AS runtime
WORKDIR /app
COPY --from=builder /app/target/release/my-app /usr/local/bin
EXPOSE 8080
ENTRYPOINT ["/usr/local/bin/my-app"]
```

## Reading PORT from environment {{ anchor: true, id: 'reading-port-from-environment' }}

```rust
use std::env;

let port = env::var("PORT").unwrap_or_else(|_| "8080".to_string());
let addr = format!("0.0.0.0:{}", port);
```

## Axum example {{ anchor: true, id: 'axum-example' }}

```rust
use axum::{routing::get, Router};
use std::env;

#[tokio::main]
async fn main() {
    let app = Router::new().route("/", get(|| async { "Hello from Temps!" }));
    let port = env::var("PORT").unwrap_or_else(|_| "8080".to_string());
    let listener = tokio::net::TcpListener::bind(format!("0.0.0.0:{}", port))
        .await
        .unwrap();
    axum::serve(listener, app).await.unwrap();
}
```

## Managed PostgreSQL {{ anchor: true, id: 'managed-postgresql' }}

Create a PostgreSQL database under **Databases → Create database**, then link it from your project's **Databases** page. Temps injects the connection string as `POSTGRES_URL`; read it with `sqlx` or `diesel`:

```rust
let pool = sqlx::PgPool::connect(&std::env::var("POSTGRES_URL")?).await?;
```

See [Deploy with a Database](/docs/deploy-with-database) for all the injected variables.
