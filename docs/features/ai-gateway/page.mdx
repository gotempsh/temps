# AI Gateway

OpenAI-compatible AI gateway built into Temps. Use any OpenAI SDK to call OpenAI, Anthropic, Gemini, xAI, Mistral, and DeepSeek &mdash; just change the base URL. {{ className: 'lead' }}

---

## Overview {{ anchor: true, id: 'overview' }}

The AI Gateway provides a unified, OpenAI-compatible API for all major LLM providers. Your existing OpenAI SDK code works unchanged &mdash; just point it at your Temps instance.

<Row>
  <Col>
    **What's Included**
    - OpenAI API wire-compatible endpoints
    - Multi-provider routing (OpenAI, Anthropic, Gemini, xAI, Mistral, DeepSeek)
    - Tool calling / function calling across all providers
    - Vision / image attachments (base64 and URL)
    - SSE streaming with consistent format
    - Centralized API key management
    - Per-user usage tracking and analytics
    - JSON mode / structured output
  </Col>
  <Col>
    **Why It Matters**
    - Zero code changes &mdash; works with any OpenAI SDK
    - Centralized key management (devs never see API keys)
    - Switch providers without changing client code
    - Built-in usage analytics and cost tracking
    - Self-hosted &mdash; your data stays on your infrastructure
    - No per-request fees beyond provider costs
    - Transparent translation for Anthropic and Gemini
  </Col>
</Row>

### Key Features

<Properties>
  <Property name="Drop-In Replacement">
    100% OpenAI SDK compatible. Works with Python, Node.js, Go, Rust, and any other OpenAI client library.
  </Property>
  <Property name="Transparent Translation">
    Automatically translates requests/responses for Anthropic Messages API and Gemini generateContent API.
  </Property>
  <Property name="Vision Support">
    Send images as base64 data URIs or HTTP URLs. Translated to each provider's native format automatically.
  </Property>
  <Property name="Tool Calling">
    OpenAI-format tools work across all providers. Function definitions, tool_choice, and tool results are translated transparently.
  </Property>
  <Property name="Streaming">

  </Property>
  <Property name="Usage Analytics">
    Track token usage, costs, and request counts per user, model, and provider.
  </Property>
</Properties>

## Quick Start {{ anchor: true, id: 'quick-start' }}

Point any OpenAI SDK at your Temps instance. The only changes are `base_url` and `api_key`.

<CodeGroup title="Setup">

```python {{ title: 'Python' }}
from openai import OpenAI

client = OpenAI(
    base_url="https://your-temps-instance.com/api/ai/v1",
    api_key="your-temps-api-key",
)

response = client.chat.completions.create(
    model="gpt-4o",  # or "claude-sonnet-4-20250514", "gemini-2.5-pro", etc.
    messages=[
        {"role": "user", "content": "Hello!"}
    ],
)

print(response.choices[0].message.content)
```

```typescript {{ title: 'Node.js' }}
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://your-temps-instance.com/api/ai/v1",
  apiKey: "your-temps-api-key",
});

const response = await client.chat.completions.create({
  model: "gpt-4o", // or "claude-sonnet-4-20250514", "gemini-2.5-pro", etc.
  messages: [
    { role: "user", content: "Hello!" }
  ],
});

console.log(response.choices[0].message.content);
```

```bash {{ title: 'cURL' }}
curl https://your-temps-instance.com/api/ai/v1/chat/completions \
  -H "Authorization: Bearer your-temps-api-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-4o",
    "messages": [{"role": "user", "content": "Hello!"}]
  }'
```

</CodeGroup>

## Supported Providers {{ anchor: true, id: 'providers' }}

The gateway routes each request by its exact model ID: it looks the ID up in the model catalogs of your active provider keys (the models listed under each key in **AI Gateway → AI providers**) and sends the request to the key that serves it. Only when no catalog lists the model does it fall back to the model-name prefixes of the built-in providers:

| Model Prefix | Provider | Examples |
|---|---|---|
| `gpt-*`, `o1-*`, `o3-*` | OpenAI | `gpt-4o`, `gpt-4o-mini`, `o3-mini` |
| `claude-*` | Anthropic | `claude-sonnet-4-20250514`, `claude-haiku-4-5-20251001` |
| `gemini-*` | Google Gemini | `gemini-2.5-pro`, `gemini-2.5-flash` |
| `grok-*` | xAI | `grok-3`, `grok-3-mini` |
| `mistral-*`, `codestral-*` | Mistral | `mistral-large-latest`, `codestral-latest` |
| `deepseek-*` | DeepSeek | `deepseek-chat`, `deepseek-reasoner` |

<Note>
  All providers use the same OpenAI-compatible API format. The gateway handles protocol translation automatically for Anthropic and Gemini.
</Note>

If two keys that reach different upstreams both serve the same model ID, the request is refused with `409 ambiguous_model` rather than sent to either. Pick one with the `X-Temps-Provider-Key-Id: <key id>` header. Disabling the model on the other keys also resolves it, except on a self-hosted key: a self-hosted key that lists a model keeps hosting it even while the model is disabled there (so it is never handed to a vendor by accident), and requests for that model must then pin a key with the header. Two keys of the same provider on the same endpoint are interchangeable and are not ambiguous.

## Self-hosted Providers {{ anchor: true, id: 'self-hosted' }}

Add a **Self-hosted (OpenAI-compatible)** provider to use a model server on your own network, such as MLX, vLLM, llama.cpp, LM Studio or Ollama's OpenAI API:

1. Enter the server's base URL including `/v1`, for example `http://10.0.0.5:8000/v1`. The API key is optional, since many local servers run without authentication.
2. Allow Temps to reach the address. Private and loopback addresses are blocked by default. Either an administrator enables **Trust this private address for this key only**, which lets this one key reach that exact IP address and port, or the address is added under **Settings → Security → Trusted private networks**, which every outbound feature honours. Trusting on the key requires the base URL to use an IP address, and cloud metadata and link-local addresses can never be trusted.
3. Click **Load models**. Temps lists every model the server reports at `/models`, with no name filter, and you pick the default model. Temps verifies the connection with that model before saving.
4. Declare what the server supports: streaming, tool calling, embeddings and the Responses API. Requests that need an undeclared capability are refused before anything is sent.

Every model the server lists is routed only to that server. A request for a model it hosts is never sent to OpenRouter or another vendor, even when the ID looks like `vendor/model`, and if the model is disabled there or the server stops listing it, the request fails with `model_unavailable` instead of falling back. To use another key for such a model on purpose, send the `X-Temps-Provider-Key-Id` header.

AI chat follows the declared capabilities. A self-hosted key that does not declare streaming cannot serve chat: new chats default to the first key that can, and a chat pinned to such a key explains that the key does not declare streaming. On a key that does not declare tool calling, chat runs without Temps tools, and the assistant tells you that the provider cannot look up data or take actions. Other callers that send tools to such a key get an explicit `capability_not_declared` error.

<Note>
  Plain `http://` is accepted only for trusted private addresses, so an API key or a prompt is never sent unencrypted over the internet. Use `https://` for any provider on a public address. Keys created before this rule that point at a public `http://` URL are refused at request time with that reason; change their base URL to `https://`.
</Note>

response = client.chat.completions.create(

        {"role": "user", "content": "Write a Python function to calculate fibonacci numbers."},

    ],
    temperature=0.7,
    max_tokens=500,

## Vision & Image Attachments {{ anchor: true, id: 'vision' }}

Send images to vision-capable models. The gateway translates image formats automatically for each provider.

### Base64 Image

<CodeGroup title="Send base64 image">

```python {{ title: 'Python' }}
import base64

# Read image and encode to base64
with open("screenshot.png", "rb") as f:
    image_data = base64.standard_b64encode(f.read()).decode("utf-8")

response = client.chat.completions.create(
    model="gpt-4o",  # or claude-sonnet-4-20250514, gemini-2.5-pro
    messages=[
        {
            "role": "user",
            "content": [
                {"type": "text", "text": "What's in this image? Describe it in detail."},
                {
                    "type": "image_url",
                    "image_url": {
                        "url": f"data:image/png;base64,{image_data}"
                    },
                },
            ],
        }
    ],
    max_tokens=1000,
)

print(response.choices[0].message.content)
```

```typescript {{ title: 'Node.js' }}
import fs from "fs";

// Read image and encode to base64
const imageData = fs.readFileSync("screenshot.png").toString("base64");

const response = await client.chat.completions.create({
  model: "gpt-4o", // or claude-sonnet-4-20250514, gemini-2.5-pro
  messages: [
    {
      role: "user",
      content: [
        { type: "text", text: "What's in this image? Describe it in detail." },
        {
          type: "image_url",
          image_url: {
            url: `data:image/png;base64,${imageData}`,
          },
        },
      ],
    },
  ],
  max_tokens: 1000,
});

console.log(response.choices[0].message.content);
```

```bash {{ title: 'cURL' }}
# Base64 encode an image (macOS)
IMAGE_B64=$(base64 -i screenshot.png)

curl https://your-temps-instance.com/api/ai/v1/chat/completions \
  -H "Authorization: Bearer your-temps-api-key" \
  -H "Content-Type: application/json" \
  -d "{
    \"model\": \"gpt-4o\",
    \"messages\": [{
      \"role\": \"user\",
      \"content\": [
        {\"type\": \"text\", \"text\": \"What's in this image?\"},
        {\"type\": \"image_url\", \"image_url\": {\"url\": \"data:image/png;base64,${IMAGE_B64}\"}}
      ]
    }],
    \"max_tokens\": 1000
  }"
```

## Tool Calling (Function Calling) {{ anchor: true, id: 'tool-calling' }}

Define tools using the OpenAI format. The gateway translates them to each provider's native format.

<CodeGroup title="Tool calling">

```python {{ title: 'Python' }}
import json

tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "Get current weather for a city",
            "parameters": {
                "type": "object",
                "properties": {
                    "location": {
                        "type": "string",
                        "description": "City name, e.g. 'London'"
                    },
                    "unit": {
                        "type": "string",
                        "enum": ["celsius", "fahrenheit"],
                        "description": "Temperature unit"
                    }
                },
                "required": ["location"]
            }
        }
    }
]

# Step 1: Send message with tools
response = client.chat.completions.create(
    model="claude-sonnet-4-20250514",  # works with any provider
    messages=[
        {"role": "user", "content": "What's the weather like in London?"}
    ],
    tools=tools,
)

message = response.choices[0].message

# Step 2: Check if the model wants to call a tool
if message.tool_calls:
    tool_call = message.tool_calls[0]
    args = json.loads(tool_call.function.arguments)
    print(f"Model wants to call: {tool_call.function.name}({args})")

    # Step 3: Execute the tool and send the result back
    weather_result = get_weather(args["location"])  # your function

    follow_up = client.chat.completions.create(
        model="claude-sonnet-4-20250514",
        messages=[
            {"role": "user", "content": "What's the weather like in London?"},
            message,  # assistant message with tool_calls
            {
                "role": "tool",
                "tool_call_id": tool_call.id,
                "content": json.dumps(weather_result),
            },
        ],
        tools=tools,
    )

    print(follow_up.choices[0].message.content)
```

```typescript {{ title: 'Node.js' }}
const tools = [
  {
    type: "function" as const,
    function: {
      name: "get_weather",
      description: "Get current weather for a city",
      parameters: {
        type: "object",
        properties: {
          location: { type: "string", description: "City name" },
          unit: { type: "string", enum: ["celsius", "fahrenheit"] },
        },
        required: ["location"],
      },
    },
  },
];

// Step 1: Send message with tools
const response = await client.chat.completions.create({
  model: "claude-sonnet-4-20250514", // works with any provider
  messages: [
    { role: "user", content: "What's the weather like in London?" }
  ],
  tools,
});

const message = response.choices[0].message;

// Step 2: Check if the model wants to call a tool
if (message.tool_calls) {
  const toolCall = message.tool_calls[0];
  const args = JSON.parse(toolCall.function.arguments);
  console.log(`Calling: ${toolCall.function.name}(${JSON.stringify(args)})`);

  // Step 3: Execute the tool and send result back
  const weatherResult = await getWeather(args.location);

  const followUp = await client.chat.completions.create({
    model: "claude-sonnet-4-20250514",
    messages: [
      { role: "user", content: "What's the weather like in London?" },
      message, // assistant message with tool_calls
      {
        role: "tool",
        tool_call_id: toolCall.id,
        content: JSON.stringify(weatherResult),
      },
    ],
    tools,
  });

  console.log(followUp.choices[0].message.content);
}
```

</CodeGroup>

### Tool Choice

Control whether the model should call tools:

```python {{ title: 'Tool choice options' }}
# Let the model decide (default)
tool_choice="auto"

# Force the model to call a tool
tool_choice="required"

# Force a specific tool
tool_choice={"type": "function", "function": {"name": "get_weather"}}

# Don't use tools (even if provided)
tool_choice="none"
```

## Streaming {{ anchor: true, id: 'streaming' }}

SSE streaming works identically to the OpenAI API. All providers produce the same `data: {...}\n\n` format.

<CodeGroup title="Streaming">

```python {{ title: 'Python' }}
stream = client.chat.completions.create(
    model="gemini-2.5-flash",
    messages=[
        {"role": "user", "content": "Write a haiku about deployment automation."}
    ],
    stream=True,
)

for chunk in stream:
    content = chunk.choices[0].delta.content
    if content:
        print(content, end="", flush=True)

print()  # newline at end
```

```typescript {{ title: 'Node.js' }}
const stream = await client.chat.completions.create({
  model: "gemini-2.5-flash",
  messages: [
    { role: "user", content: "Write a haiku about deployment automation." }
  ],
  stream: true,
});

for await (const chunk of stream) {
  const content = chunk.choices[0]?.delta?.content;
  if (content) {
    process.stdout.write(content);
  }
}

console.log(); // newline at end
```

</CodeGroup>

## Provider Key Management {{ anchor: true, id: 'key-management' }}

Manage provider API keys through the Temps admin panel or API. Keys are encrypted at rest using AES-256-GCM.

```bash {{ title: 'Add a provider key via API' }}
# Add an OpenAI key
curl -X POST https://your-temps-instance.com/api/ai/providers \
  -H "Authorization: Bearer your-admin-api-key" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "openai",
    "api_key": "sk-...",
    "display_name": "Production OpenAI Key"
  }'

# Add an Anthropic key
curl -X POST https://your-temps-instance.com/api/ai/providers \
  -H "Authorization: Bearer your-admin-api-key" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "anthropic",
    "api_key": "sk-ant-...",
    "display_name": "Production Anthropic Key"
  }'
```

<Note>
  Developers only need a Temps API key. Provider API keys are managed centrally by administrators and never exposed to end users.

## Rate Limits & Budgets {{ anchor: true, id: 'limits' }}

Calls made with a project's deployment token are limited **per project**, so one noisy project cannot exhaust the shared provider keys. Two limits apply, and both are configured under **AI → Limits** in the console or through the API:

<Properties>
  <Property name="Requests per minute">
    A sliding-window cap on gateway requests. Defaults to **300 per minute per project** when nothing is configured.
  </Property>
  <Property name="Monthly budget">
    A cap on operator-funded spend per calendar month (UTC), estimated from the model price list. Off by default. Requests that use a caller-supplied provider key are not counted, and are not refused when the budget is spent; they still count toward the request rate.
  </Property>
</Properties>

Limits resolve from the most specific scope: the project's own override, then the instance default, then the built-in default. A blank value **inherits** from the next scope; `0` means **unlimited**. The budget is expressed in microcents (1 USD = 1,000,000), the same unit the usage log records.

```bash {{ title: 'Set limits' }}
# Instance default: 120 requests/minute, $50.00/month
curl -X PUT https://your-temps-instance.com/ai/limits/instance \
  -H "Authorization: Bearer your-admin-api-key" \
  -H "Content-Type: application/json" \
  -d '{"max_requests_per_minute": 120, "max_cost_per_month_microcents": 50000000}'

# One project: unlimited requests, $5.00/month
curl -X PUT https://your-temps-instance.com/ai/limits/projects/42 \
  -H "Authorization: Bearer your-admin-api-key" \
  -H "Content-Type: application/json" \
  -d '{"max_requests_per_minute": 0, "max_cost_per_month_microcents": 5000000}'

# Back to the instance defaults
curl -X DELETE https://your-temps-instance.com/ai/limits/projects/42 \
  -H "Authorization: Bearer your-admin-api-key"
```

Reading limits and spend requires an instance administrator, because they span every project; changing them requires the AI gateway write permission. A caller over either limit gets `429 Too Many Requests` with a `Retry-After` header (seconds). A rate-limit refusal returns `rate_limit_error` / `rate_limit_exceeded`; an exhausted budget returns `insufficient_quota` / `budget_exceeded`, with `Retry-After` set to the time until the month resets.

<Note>
  The budget is a soft cap: spend is read from the usage log through a short cache, so a burst can overshoot it slightly. If the usage log cannot be read, requests are allowed rather than blocked.
</Note>

Project-scoped structured output (`/projects/{project_id}/ai/structured-output/stream`) shares the same rate limit and budget. The provider stream carries no token counts, so its usage is estimated from the request and response sizes and priced from the model list. Every usage log entry made with a deployment token records its `project_id` and `token_id`, taken from the authenticated token and never from request headers. Filter the log with `?project_id=`, or get per-project totals from `GET /ai/usage/by-project` (administrators only).

## Usage & Analytics {{ anchor: true, id: 'usage' }}

Track token usage and costs per user, model, and provider through the Temps dashboard or API.

```bash {{ title: 'Query usage' }}
# Get usage summary for a project
curl https://your-temps-instance.com/api/ai/usage/summary?period=7d \
  -H "Authorization: Bearer your-admin-api-key"
```

  "prompt_tokens": 1923847,
  "completion_tokens": 923545,

    {"model": "claude-sonnet-4-20250514", "requests": 481, "total_tokens": 924392},
    {"model": "gemini-2.5-pro", "requests": 200, "total_tokens": 400000}
